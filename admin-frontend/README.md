# FluxSwap 管理端

FluxSwap 管理端是一个独立的 Next.js 前端，用来管理协议的农场、奖励分发、金库治理和代币配置。

它的定位不是通用后台，而是偏协议运营和链上管理控制台。核心目标有三个：

- 让管理者快速看清协议当前状态
- 让农场、金库、代币治理操作可以直接落地
- 让本地链和测试网联调时，问题更容易定位

---

## 1. 项目概览

当前管理端主要面向两类使用场景：

- 本地 Hardhat 链联调
- Sepolia 测试网部署后的管理操作

当前覆盖的协议管理范围：

- 农场与奖励管理
- 金库管理
- 代币管理
- 管理日志回溯
- 协议概览监控

技术栈：

- Next.js 16
- React 19
- TypeScript
- wagmi
- viem
- RainbowKit
- Tailwind CSS 4

## 5. 首页 / 概览页

页面地址：

- `/`
- `/overview` 会重定向到 `/`

### 5.1 页面定位

首页是管理端的总入口，用来先看协议整体状态，再进入具体模块处理问题。

它更像一张“协议值班面板”，而不是操作表单页面。

### 5.2 页面主要模块

#### 1）顶部概览区

显示内容：

- 页面标题
- 最近刷新时间
- 手动刷新按钮
- 三个快捷入口
  - 农场管理
  - 金库管理
  - 代币管理

作用：

- 让管理者进入页面第一眼就知道当前处于哪个总控页面
- 快速跳转到最常用的后台模块

#### 2）全局状态提示

可能出现的提示包括：

- 当前网络不受支持
- 当前网络缺少管理合约配置
- 概览数据暂时不可用

这些提示的目的，是在没有数据时区分到底是：

- 网络不对
- 配置没接上
- RPC 或链上数据暂时不可用

#### 3）顶部四个摘要指标

当前展示的指标有：

- 活跃农场
- 待分发奖励
- 可用授权
- 白名单覆盖

这些指标用于快速判断：

- 农场是否在正常运转
- 奖励是否积压
- 金库对管理合约的可用授权是否还够
- 当前代币配置是否完整

#### 4）整体状态图谱

这个模块把协议路径串起来展示：

- 白名单资产
- 金库
- 管理合约
- 农场池
- 奖励领取

目的：

- 让人从“协议流程”角度看，而不是只盯着单个数字
- 快速定位问题是在资产准入、金库、分发还是农场侧

#### 5）健康度

健康度是一个综合分值，主要参考：

- 是否有启用中的农场
- 总权重是否为 0
- 金库是否暂停
- 金库奖励余额是否为 0
- 管理合约可用授权是否为 0
- 白名单覆盖是否不足

它是一个运营视角的信号灯，不是链上真实指标。

#### 6）待处理事项

这个模块会把最需要处理的问题排出来，例如：

- 暂无启用农场
- 金库处于暂停状态
- 金库奖励余额不足
- 管理合约授权不足
- 白名单覆盖不完整

作用：

- 比起让用户自己读一堆表，更直接告诉他“现在该处理什么”

#### 7）奖励容量

通过可视化方式展示三类值：

- 金库奖励余额
- 已授权额度
- 待分发奖励

适合快速判断：

- 金库里是不是有足够奖励币
- 管理合约是不是有足够额度去执行分发
- 当前待分发积压是否过高

#### 8）农场权重

展示：

- 各农场权重占比
- 总权重
- 各池是否启用
- 各池质押规模

主要帮助判断：

- 奖励分配是否过度集中
- 某些农场是否有权重但已失去运营意义

#### 9）管理事件频率

当前是一个基于最近 `20,000` 个区块的事件热力图。

展示内容：

- 农场管理事件数量
- 金库管理事件数量
- 总事件数
- 时间范围
- 每格代表的近似时间跨度
- 时间轴刻度（开始 / 25% / 50% / 75% / 最新）

鼠标悬停到单个格子时还会看到：

- 该格对应的时间段
- 对应区块范围
- 农场事件数
- 金库事件数
- 总事件数

用途：

- 观察最近一段时间管理操作是否集中
- 判断协议最近是否处于高频治理/高频调整状态

### 5.3 数据来源

首页数据主要直接读取链上：

- 管理合约
- 金库合约
- 奖励代币
- 质押池合约
- 最近区块窗口内的治理/管理事件

### 5.4 刷新策略

当前逻辑：

- 首次进入页面自动加载一次
- 之后只有手动点击“刷新”才会再次拉取

这样做是为了避免自动循环刷新。

## 6. 农场管理页

页面地址：

- `/farm`

### 6.1 页面定位

农场页负责处理质押池和奖励分发，是管理端里最偏“激励配置”的页面。

### 6.2 页面主要模块

#### 1）页面头部

提供：

- 页面说明
- 刷新按钮
- 未连接钱包时的连接钱包入口

#### 2）农场状态卡片

当前显示的信息包括：

- 总农场数
- 启用中农场数
- 总权重
- 待分发奖励

作用：

- 快速了解当前农场系统是不是“开着”
- 奖励是否已经有积压

#### 3）权限与合约状态

这里会展示多个关键角色及当前钱包是否匹配：

- 工厂所有者
- 管理合约所有者
- 管理合约操作员
- 金库及其操作员

对应关系大致是：

- 工厂所有者：可创建质押池
- 管理合约所有者：可调整池权重、启停
- 管理合约操作员：可分发奖励

作用：

- 先判断“不能操作”是不是因为权限不够

#### 4）创建 LP 质押池

支持两种方式：

- 从下拉中选择交易对
- 手动输入 LP 代币地址

可配置内容：

- LP 代币地址
- 奖励权重
- 创建后是否启用

适用场景：

- 想把某个交易对接入农场激励

#### 5）创建单币质押池

支持两种方式：

- 从预设代币中选择
- 手动输入代币地址

可配置内容：

- 代币地址
- 奖励权重
- 创建后是否启用

适用场景：

- 给某个代币做单币质押激励

#### 6）分发奖励

这个模块是农场页的重要操作入口。

展示内容：

- 奖励代币
- 待分发数量
- 启用农场数
- 金库余额
- 已授权额度
- 今日剩余额度
- 金库状态
- 金库操作员

可执行操作：

- 输入奖励数量
- 发起一次分发

### 6.3 分发前的限制判断

页面会根据当前链上状态给出“能不能分发”的反馈，常见阻塞原因包括：

- 当前钱包权限不足
- 没有启用中的农场
- 奖励数量格式不正确
- 金库已暂停
- 金库余额不足
- 金库给管理合约的授权不足
- 每日额度不足

### 6.4 农场列表

农场表格会展示每个池子的关键状态，并允许进行管理：

- 池子地址
- 质押资产
- 权重
- 启用状态
- 质押规模
- 奖励相关状态

可进行的操作：

- 搜索池子
- 只看启用中的池子
- 修改权重
- 启用/停用池子

### 6.5 数据来源

农场页主要读取：

- `FluxPoolFactory`
- `FluxMultiPoolManager`
- 各个 `StakingRewards` 质押池
- 相关奖励代币与金库状态

### 6.6 典型使用流程

#### 创建新农场

1. 确认当前钱包具有创建权限
2. 选择 LP 交易对或单币代币
3. 填入奖励权重
4. 选择是否创建后启用
5. 提交交易

#### 分发奖励

1. 确认当前钱包可分发
2. 查看金库余额、授权和剩余额度
3. 输入分发数量
4. 提交交易

#### 更新农场参数

1. 在农场列表中找到目标池子
2. 修改权重或启停状态
3. 发起更新交易

## 7. 金库管理页

页面地址：

- `/treasury`

### 7.1 页面定位

金库页是整个管理端里风险最高的一页，用于处理资产权限、治理操作和实际划拨。

它同时承担两类工作：

- 治理排队与执行
- 日常资产划拨

### 7.2 页面主要模块

#### 1）页面头部

提供：

- 页面说明
- 刷新按钮

#### 2）金库状态卡片

展示：

- 金库状态
- 配置资产数
- 排队中的治理操作数
- 治理延迟

作用：

- 一眼判断金库是否处于暂停状态
- 当前是否积压了治理操作

#### 3）权限与治理地址

展示：

- 金库地址
- 多签地址
- 守护者地址
- 操作员地址
- 当前连接钱包地址
- 当前钱包是否对应多签 / 守护者 / 操作员

作用：

- 明确当前钱包在金库体系中的角色

#### 4）创建治理操作

这是“高风险变更”的入口。

当前支持的治理操作类型包括：

- 资产白名单
- 接收方白名单
- 每日支出额度
- 授权花费者额度
- 撤销花费者额度
- 更新守护者
- 更新操作员
- 更新治理延迟
- 紧急提取代币
- 紧急提取 ETH

表单内容会根据操作类型动态变化。

常见字段包括：

- 操作类型
- 排队延迟（秒）
- 资产
- 白名单状态
- 目标地址
- 花费者地址
- 授权额度
- 每日额度
- 新治理延迟
- 紧急提取数量
- 接收地址

点击提交后，逻辑是：

- 由多签发起
- 生成治理操作
- 进入排队
- 页面本地保留参数记录，供后续安全执行

#### 5）金库划拨

这是偏日常操作的资金发放入口。

可配置：

- 选择资产
- 输入接收地址
- 输入划拨数量

同时会显示：

- 金库余额
- 今日额度剩余

权限要求：

- 当前钱包为操作员或多签
- 金库未暂停
- 当前地址和金额满足允许条件

#### 6）待处理治理操作

这个表格展示最近窗口内已排队但未完成的治理动作。

显示内容包括：

- 操作总数
- 可执行数量
- 操作类型
- 状态
- 执行时间
- 本地创建时间
- 具体参数

支持的交互：

- 展开查看详情
- 执行治理操作
- 取消治理操作

这里的“执行”依赖本地保留的元数据参数，所以不是只看链上事件就能完全恢复。

#### 7）金库资产表

展示每个配置资产的状态：

- 资产名称和地址
- 是否在白名单内
- 金库余额
- 已授权额度
- 每日额度
- 今日已使用额度

用途：

- 看金库里到底有什么
- 看哪些资产已经可用于分发或划拨
- 看额度是不是快用完了

#### 8）风险提示

这一块主要是提醒：

- 白名单
- 授权
- 每日额度
- 暂停
- 紧急提取

都属于高风险金库操作，不适合随意执行。

### 7.3 权限模型

金库页当前主要区分三类角色：

- 多签
- 守护者
- 操作员

大体规则如下：

- 多签：可发起治理、执行部分关键操作
- 守护者：偏紧急控制，例如暂停相关能力
- 操作员：偏日常划拨和业务执行

### 7.4 数据来源

金库页主要读取：

- `FluxSwapTreasury`
- 管理合约地址
- 代币合约余额和额度
- 金库治理事件与本地元数据记录

### 7.5 典型使用流程

#### 将某代币加入金库白名单

1. 在代币页点击“去金库”
2. 自动带着 `setAllowedToken` 参数跳到金库页
3. 检查治理参数
4. 多签提交排队
5. 达到延迟后执行

#### 调整某代币每日额度

1. 打开治理表单
2. 选择 `setDailySpendCap`
3. 选择目标资产
4. 填入新额度
5. 发起治理排队

#### 向白名单地址划拨资产

1. 选择资产
2. 输入接收地址
3. 输入数量
4. 检查余额与今日额度
5. 提交划拨交易

## 8. 代币管理页

页面地址：

- `/tokens`

### 8.1 页面定位

代币页不直接负责改链上配置本身，它更像“配置校验 + 协议可见性检查”页面。

核心问题是：

- 管理端里配的代币，链上读出来是不是一致
- 这些代币在协议里有没有实际用途
- 这些代币如果已经被协议使用，是否已经在金库里放行

### 8.2 页面主要模块

#### 1）页面头部

提供：

- 页面说明
- 刷新按钮

#### 2）状态摘要卡片

当前聚焦以下维度：

- 已配置代币数量
- 链上信息匹配数量
- 金库白名单覆盖数量
- 待检查数量
- 协议使用中的代币数量

#### 3）协议使用概览

汇总代币在协议中的使用情况：

- 是否存在交易对
- 是否用于单币池
- 是否是奖励代币
- 是否存在已使用但尚未通过金库治理放行的代币

#### 4）行动建议

这个模块会把更值得优先处理的代币问题放到前面，例如：

- 代币已经参与协议使用，但还没进入金库白名单
- 链上配置与前端配置不一致

#### 5）配置风险

展示当前存在问题的代币：

- 符号不一致
- 名称不一致
- 精度不一致
- 链上读取失败

这个模块偏“配置审计”作用。

#### 6）金库放行待办

专门显示：

- 已经参与协议业务
- 但尚未在金库中放行

并且可以直接跳到金库页，带上预填参数去发起治理。

#### 7）代币列表

支持：

- 搜索
- 按状态筛选
- 按字段排序

筛选维度包括：

- 全部
- 只看有配置差异的
- 只看协议正在使用的
- 只看已进金库白名单的
- 只看未进金库白名单的

列表项会展示：

- 配置值
- 链上值
- 协议用途
- 金库白名单状态
- 操作建议

### 8.3 当前数据逻辑

代币页以 `src/config/tokens.ts` 里的配置为基础，再去链上逐个比对：

- `symbol`
- `name`
- `decimals`
- `totalSupply`
- 是否在金库白名单
- 金库余额
- 是否存在交易对
- 是否已被单币池使用
- 是否是奖励币

### 8.4 页面定位边界

代币页现在不承担“链上新增注册代币”的职责，它当前是：

- 前端配置视角的代币总览
- 协议用途与治理状态检查页

不是完全链上自治的代币注册中心。

## 9. 管理日志页

页面地址：

- `/logs`

### 9.1 页面定位

日志页是一个轻量回溯页，用来查看最近的农场和金库管理行为。

它不是完整审计系统，但足够用于日常联调和排查。

### 9.2 页面主要模块

#### 1）页面头部

提供：

- 页面说明
- 刷新按钮

#### 2）最近操作表格

当前默认读取：

- 最近 `20,000` 个区块
- 最多 `80` 条事件

展示字段：

- 动作
- 内容
- 区块号
- 交易哈希

模块范围：

- 金库

金库侧主要包括：

- 更新每日额度
- 暂停金库

### 9.4 使用场景

这个页面适合做这些事：

- 回看最近谁做了什么管理操作
- 本地链联调时确认交易是否真的发出
- 配合首页的管理事件频率使用

### 9.5 局限

它当前只是最近窗口日志，不是长期归档系统：

- 不做数据库级持久存储
- 不做跨很长时间范围检索
- 不做复杂筛选

## 12. 本地联调建议

推荐顺序：

1. 启动本地 Hardhat 链
2. 部署合约
3. 更新管理端读取的合约地址
4. 启动管理端
5. 连接钱包并切到本地链

如果你重启了本地链，但管理端还显示旧内容，优先检查：

- 钱包是否还连着旧网络实例
- 合约地址是否还是旧地址
- 前端配置是否已更新
- 本地链里是否真的已经重新部署完成

## 13. 常见问题

### 13.1 页面没有数据

优先检查：

- 钱包是否连接
- 当前网络是否受支持
- RPC 是否可用
- 管理合约地址是否存在
- 金库地址是否存在
- 本地链是否已经重新部署

### 13.2 本地链重启后还是旧数据

通常不是页面缓存，而是前端仍然指向旧部署地址。

重点检查：

- `contracts.generated.ts`
- 钱包网络
- 本地链实例是否真的更新

### 13.3 概览页为什么不自动一直刷新

这是有意为之。

当前策略是：

- 首次进入自动加载一次
- 之后手动刷新

目的是避免自动刷新循环，也避免在链上调试时不停打 RPC。

### 13.4 日志为什么没有很久以前的数据

因为当前日志页只拉最近窗口：

- 最近 `20,000` 个区块
- 最多 `80` 条事件

它偏联调和最近变更回溯，不是历史归档系统。

### 13.5 代币页为什么不能直接新增链上代币注册

因为当前机制是：

- 链上完全支持 ERC20
- 管理端只负责“配置已知代币”和“判断是否应该进入金库治理范围”

它不是一个链上注册表后台。
